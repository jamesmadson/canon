# Canon MCP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `canon mcp` lets any MCP-speaking agent add prototype URLs to Canon boards, update them (keeping old URLs as versions), find them, open a view in the open Canon tab, and return deep links — through a paired, mutually authenticated loopback bridge.

**Architecture:** The agent starts `canon mcp` (MCP over stdio, hand-rolled JSON-RPC). The same process runs a loopback HTTP server on the first free port in 47800–47809. The open Canon tab long-polls each port in that range: it asks `/who`, then `POST /poll` signed with that agent's pairing secret; the MCP hands back queued commands and signs its response so the tab knows it's real. The tab runs commands against its IndexedDB store and replies on its next poll. Only one tab bridges at a time (Web Locks); others reload on a BroadcastChannel ping.

**Tech Stack:** Node ≥20 plain JS, `node:*` only (cli/); TypeScript + Preact/htm (src/app/); WebCrypto HMAC-SHA256 in the tab, `node:crypto` in the MCP; vitest.

**Spec:** `docs/superpowers/specs/2026-10-23-canon-mcp-design.md`

## Global Constraints

- CLI stays zero-dependency: no MCP SDK, no WebSocket library. `cli/package.json` `dependencies` stays `{}`.
- `engines.node` is `>=20`.
- MCP stdout carries JSON-RPC only, one message per line. Every log goes to stderr.
- Bind `127.0.0.1` only. Ports 47800–47809.
- Allowed origins: `https://jamesmadson.github.io`; with `--dev` also `http://localhost:4321` and `http://127.0.0.1:4321`. Allowed Host: `127.0.0.1:<port>` or `localhost:<port>`.
- Canon app base: `https://jamesmadson.github.io/canon/app/`; with `--dev`, `http://localhost:4321/canon/app/`.
- Pairing file `~/.canon/mcp.json`, mode 0600, directory 0700, written atomically (tmp + rename).
- The MCP never reads files other than its pairing file, never fetches URLs, never runs commands.
- Prototype URLs: `http:` and `https:` only.
- No deletes through the MCP.
- Commit messages: plain sentences like the existing history ("Build …", "Wire …"); no `feat:` prefixes and no Claude attribution lines.
- Gate: `npm test` from the repo root runs both suites (see `vitest.config.ts`).

## Review Focus

1. A `javascript:`, `data:`, `file:` or `blob:` URL passed to `canon_add`/`canon_update` is refused with a plain message — an iframe `src` like that would run inside Canon. Pinned in Task 2 and Task 6.
2. A name that matches two frames ("onboarding" vs "onboarding v2") is never guessed: the result lists the matches and asks the agent to choose. Exact (case-insensitive) match wins over substring. Pinned in Task 2.
3. Canon closed, or open but unpaired: a tool call answers within 3 s saying so, with the open link (and the pairing link if unpaired), never hangs. Pinned in Task 5.
4. A second agent session starting while the first runs takes the next free port and both keep working. Pinned in Task 5.
5. A `path` like `//evil.example/x` or `https://evil.example` must not move a frame off its own origin; it is refused. Pinned in Task 1.

  // MAC = hex(HMAC-SHA256(secretHex→bytes, `${role}\n${agentId}\n${ts}\n${nonce}\n${payload}`))

### Task 5: The loopback bridge

**Files:**
- Create: `cli/src/mcp/bridge.js`
- Test: `cli/tests/mcp-bridge.test.js`

**Interfaces:**
- Consumes: Tasks 3, 4.
- Produces:
  ```
  startBridge({ agentId, name, pairingFile, dev = false, ports = [47800..47809] })
    -> Promise<{ port, send(op: string, args: object, { timeoutMs = 10_000 } = {}) -> Promise<Reply>, connected() -> boolean, close() }>
  type Reply = { ok: true, result: any } | { ok: false, error: 'not-connected' | 'timeout' | string }
  ```
- HTTP, `node:http`, bound to `127.0.0.1`, first free port in the range (`EADDRINUSE` → next; all taken → reject `No free port in 47800–47809.`).
- Every request: Host must match, Origin must be allowed (Global Constraints), else 403 with no body. `OPTIONS` answers CORS for allowed origins: `Access-Control-Allow-Origin: <origin>`, `-Methods: GET, POST`, `-Headers: content-type`, `Access-Control-Allow-Private-Network: true`, `Vary: Origin`.
- `GET /who` → `{ agentId, name }`.
- `POST /poll`, body `{ agentId, tabId, ts, nonce, mac, payload }` where `payload` is a JSON string `{ replies: [{ id, ok, result?, error? }] }`. Reject (401) on bad MAC, replay, wrong agentId, or `claimPairing` false. Hold up to 25 s waiting for a command; answer `{ ts, nonce: <request nonce>, mac, payload }` with payload JSON `{ commands: [{ id, op, args }] }`, signed role `mcp`.
- `connected()` is true while a poll is held or one ended under 3 s ago. `send` returns `{ ok: false, error: 'not-connected' }` within 3 s when not connected, `timeout` after `timeoutMs` without a reply.

- [ ] **Step 1: Write the failing tests** with a fake tab (`http.request` setting Origin/Host, signing with Task 3's `sign`):
  - wrong Origin → 403; right Origin + `Host: evil.example` → 403; OPTIONS from allowed origin carries the PNA header.
  - unsigned or mis-signed poll → 401; replayed nonce → 401; second tabId after the first claimed → 401.
  - `send('find', {})` with the fake tab polling → resolves with the tab's reply; the poll response MAC verifies as role `mcp` with the request nonce.
  - no tab: `send` resolves `{ ok: false, error: 'not-connected' }` in < 3.5 s.
  - two `startBridge` calls → ports 47800 and 47801 (use a test range like 47900–47901 to avoid clashes), both serve `/who`.
  - `--dev` origin refused unless `dev: true`.
- [ ] **Step 2: Run and see them fail** — `npx vitest run cli/tests/mcp-bridge.test.js`.
